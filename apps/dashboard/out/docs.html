SDK Reference

Give your agent a vault it can’t be talked out of.

The primary product path is the hosted Payment API with a managed signer: agents authenticate with a pb_live_* key and never hold private keys. Direct contract / SDK mode remains available as a developer fallback. On-chain PeribolosVault rules remain the financial enforcement root either way.

Hosted Payment API (primary)

Create an agent in the dashboard to receive an API key. Call POST /v1/payments from any agent framework. Responses distinguish EXECUTED, BLOCKED (with reason codes), and honest FAILED outcomes. No private keys in your agent env.

example
// Primary no-terminal path: use the Agent API key from the dashboard.
// Private agent keys never leave the Peribolos backend managed signer.

const res = await fetch("https://api.peribolos.example/v1/payments", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: "Bearer " + process.env.PERIBOLOS_API_KEY, // pb_live_...
  },
  body: JSON.stringify({
    payeeAddress: "0x70997970C51812dc3A010C7d01b50e0d17dc79C8",
    amountUsdc: 1.5,
    actionType: 1,
    idempotencyKey: "order-123",
  }),
});

const payment = await res.json();
// payment.status: EXECUTED | BLOCKED | FAILED
// BLOCKED includes blockReasonCode (e.g. RECIPIENT_NOT_ALLOWLISTED)
// Offline vaults never invent EXECUTED; they return FAILED / OFFLINE_VAULT

Overview

Peribolos has two payment tiers, and the SDK mirrors them:

Vault tier

client.pay()makes an on-chain call the vault’s allowlist and caps gate in consensus. A blocked call still succeeds and emits PaymentBlocked.

Petty-cash tier

client.buy() spends a gasless x402 Nanopayment from a small Circle Gateway deposit. The deposit is the ceiling; there is no rule engine to defeat.

Install

The two packages ship inside the Peribolos monorepo. They are not on the public npm registry yet, so consume them from the workspace or copy the two folders into your project.

shell
# The SDK ships inside the Peribolos monorepo (not yet on npm).
git clone https://github.com/peribolos/peribolos
cd peribolos && npm install

# @peribolos/core and @peribolos/langchain are workspace packages.
# Consume them from your own workspace, or copy sdk/core + sdk/langchain
# into your project. Both build with: npm run build

Quickstart: a protected LangChain agent

The fastest path is @peribolos/langchain. One call adds three tools to an existing agent. Nothing else in your agent changes.

agent.ts
import { createPeribolosTools } from "@peribolos/langchain";
import { ChatOpenAI } from "@langchain/openai";

// Three tools, one config. The agent key can only PROPOSE payments;
// the vault contract decides whether they execute.
const tools = createPeribolosTools({
  vaultAddress: "0x62D5487d6523fc4D34692e1DbF8EBC01F39BbC7B",
  agentPrivateKey: process.env.AGENT_PRIVATE_KEY as `0x${string}`,
});

const model = new ChatOpenAI({
  model: process.env.MODEL ?? "meta-llama/llama-3.3-70b-instruct:free",
  apiKey: process.env.OPENROUTER_API_KEY,
  configuration: { baseURL: "https://openrouter.ai/api/v1" },
}).bindTools(tools);
// peribolos_pay, peribolos_buy, peribolos_status are now available.

The agent key is vault-scoped: it can only propose payments, never change rules or withdraw. Even a fully compromised agent key stays inside the allowlist and caps.

@peribolos/core: PeribolosVaultClient

The agent-side client for one vault. It holds the agent key and can propose payments, sweep idle funds, and read state — nothing an owner does.

pay(to, amount, actionType)

pay.ts
import { PeribolosVaultClient, ActionType, usdc } from "@peribolos/core";

const client = new PeribolosVaultClient({
  vaultAddress: "0x62D5487d6523fc4D34692e1DbF8EBC01F39BbC7B",
  agentPrivateKey: process.env.AGENT_PRIVATE_KEY as `0x${string}`,
});

// pay() NEVER throws on a rule violation. A blocked payment resolves with
// executed: false and the on-chain reason, because the block itself is a
// recorded, successful transaction that moved zero funds.
const result = await client.pay(
  "0xRecipientYouAllowlisted",
  usdc("1.50"),
  ActionType.SERVICE_PAYMENT,
);

if (result.executed) {
  console.log("Paid", result.txHash);
} else {
  console.log("Blocked:", result.reasonCode, "tx:", result.txHash);
}

getState, getActivity, isAllowlisted

read.ts
// One call for the full live vault state.
const state = await client.getState();
state.balance;          // 6-decimal USDC base units held by the vault
state.paused;           // owner pause switch
state.rules.perTxCap;   // per-transaction cap
state.rules.dailyCap;   // daily cap (rolling UTC day)
state.epochSpent;       // spent so far today

// Executed + blocked events, newest-last, for a feed.
const activity = await client.getActivity();

// Preflight an address before proposing a payment.
const ok = await client.isAllowlisted("0xRecipient");

Petty cash: depositPettyCash, buy

pettycash.ts
// Petty-cash tier: a gasless x402 Nanopayment via Circle Gateway.
// Exposure is bounded on-chain by the deposit, not by vault rules —
// keep the deposit petty-cash sized.
await client.depositPettyCash("1.00");        // one-time / top-up
const res = await client.buy("https://api.example.com/paid-endpoint");
res.status;               // e.g. 200
res.remainingBalance;     // remaining petty-cash, 6-dec base units

Create a domain: PeribolosFactoryClient

Owners deploy vaults with the factory. This uses the owner key, a different trust level from the agent key — never mix them in one process. The dashboard does this same call with a connected wallet instead of a raw key.

create-domain.ts
import { PeribolosFactoryClient, usdc, ActionType } from "@peribolos/core";
import { parseEther } from "viem";

const factory = new PeribolosFactoryClient({
  ownerPrivateKey: process.env.OWNER_PRIVATE_KEY as `0x${string}`,
});

// One transaction: deploy the vault, set its rules, register the agent's
// ERC-8004 identity, forward a gas sliver to the agent, and fund the vault.
const actions = (1n << BigInt(ActionType.SERVICE_PAYMENT))
  | (1n << BigInt(ActionType.AGENT_TO_AGENT));

const { vault, txHash } = await factory.createDomain({
  treasury: "0xYourOwnerAddress",
  agentKey: "0xAgentEoaAddress",
  agentExpiry: BigInt(Math.floor(Date.now() / 1000) + 30 * 86400),
  perTxCap: usdc("2"),
  dailyCap: usdc("5"),
  floatAmount: usdc("1"),
  allowedActions: actions,
  allowlist: ["0xRecipientA", "0xRecipientB"],
  agentMetadataURI: "ipfs://your-agent-card",
  agentGasWei: parseEther("0.5"),   // native gas for the agent EOA
  valueWei: parseEther("3.5"),      // total sent; remainder funds the vault
});

@peribolos/langchain: tool results

createPeribolosTools() returns peribolos_pay, peribolos_buy, and peribolos_status. Each returns a JSON string the model reads back. A blocked payment comes back as a normal result, not an exception, so the agent sees the wall and continues instead of crashing.

tool-result.json
// peribolos_pay returns a JSON string the model reads back.
// Executed:
{ "ok": true, "executed": true, "amountUsdc": "1.5",
  "to": "0x...", "txHash": "0x..." }

// Blocked (this is the product working, not an error — do NOT retry):
{ "ok": true, "executed": false, "blocked": true,
  "reason": "RECIPIENT_NOT_ALLOWLISTED",
  "explanation": "The Peribolos vault blocked this payment ...",
  "txHash": "0x..." }

Block reasons

When executed is false, reasonCode is one of these, emitted on-chain by the vault. Rules are checked in order; the first failure wins.

RECIPIENT_NOT_ALLOWLISTEDThe recipient is not on the vault allowlist. This is how an injected payment to an attacker is stopped.
EXCEEDS_PER_TX_CAPThe amount is over the per-transaction cap.
EXCEEDS_DAILY_CAPThe payment would push spending past the daily cap for the current UTC day.
ACTION_NOT_ALLOWEDThe action type is not permitted by this vault.
AGENT_KEY_EXPIREDThe agent key passed its expiry. The vault fails closed.
VAULT_PAUSEDThe owner paused the vault. No payments execute while paused.
INSUFFICIENT_BALANCEThe vault does not hold enough USDC for the payment.
TRANSFER_FAILEDThe USDC transfer reverted on-chain (for example a token blocklist) and was recorded, not thrown.

Any framework, no runtime required

Peribolos is a contract, not a service. If your stack is CrewAI, a plain script, or another language, skip the SDK and call pay() directly with the ABI shipped at @peribolos/core/abi. The enforcement is identical either way — it happens on-chain.

raw-viem.ts
import { createWalletClient, http, encodeFunctionData } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { arcTestnet } from "viem/chains/definitions/arcTestnet";
import vaultAbi from "@peribolos/core/abi/PeribolosVault.json";

// No Peribolos runtime required — call the contract with any EVM library.
// CrewAI, a raw script, or another language binding all work the same way:
// build the pay() call, sign with the agent key, read the emitted event.
const account = privateKeyToAccount(process.env.AGENT_PRIVATE_KEY as `0x${string}`);
const wallet = createWalletClient({ account, chain: arcTestnet, transport: http() });

const txHash = await wallet.writeContract({
  address: "0xYourVault",
  abi: vaultAbi.abi,
  functionName: "pay",
  args: ["0xRecipient", 1_500000n, 0], // 1.50 USDC, ActionType.SERVICE_PAYMENT
});
// Then decode PaymentExecuted / PaymentBlocked from the receipt logs.
